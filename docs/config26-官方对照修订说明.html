改动 1 · 关掉 USB 端口数补丁

Configuration.tex:2991 · XhciPortLimit
"This option should be avoided whenever possible. USB port limit is imposed by the amount of used bits in locationID format and there is no possible way to workaround this without heavy OS modification. The only valid solution is to limit the amount of used ports to 15 (discarding some)."

官方口径：尽可能避免开启；15 端口上限由 locationID 的位数决定，不改动系统无法绕过；唯一有效解法是把实际端口裁剪到 15 个以内。

当前配置已启用 USBToolBox.kext + UTBMap.kext + XHCI-unsupported.kext，正是官方推荐的端口定制方案。既然端口已经裁好，这个补丁既冗余、在现代 macOS 上也不再生效，关闭它不会减少任何可用端口。

改动 2 · 内存速率与模块型号对齐

Configuration.tex:6187 · Speed ／ :5971 · Devices
"Specifies the maximum capable speed of the device, in megatransfers per second (MT/s). 0 indicates an unknown speed."
"This should include all memory slots, even if unpopulated."

Speed 是模块最大能力速率（MT/s）；Devices 要列出全部插槽，含空槽。

两条已插内存的 PartNumber 均为 KHX2666C16/16G（DDR4-2666、CL16、16 GB），额定 2666 MT/s，原填 3600 与型号不符。其余内存字段复核后全部合法：4 个插槽含 2 个 NO DIMM 空槽 ✓、MaxCapacity=137438953472（官方单位 bytes，即 128 GB）✓、FormFactor=9 DIMM ✓、Type=26 DDR4 ✓、ErrorCorrection=3 None ✓、DataWidth=TotalWidth=64（无 ECC）✓。

此项零启动风险，只影响「关于本机」的内存速率显示。如果实际开启 XMP 让内存跑在 3600，把这两处改回 3600 即可。

03

一处更正：AllowRelocationBlock 不该关

上一份《Booter 内存映射组指南》把 AllowRelocationBlock=开 列为「唯一值得复查项」，措辞偏强。把官方原文读完后需要更正：

Configuration.tex:1477 · AllowRelocationBlock（末句）
"Hibernation is not supported when booting with a relocation block, which will only be used if required when the quirk is enabled."

即使启用该 quirk，relocation block 也只在确实需要时才会被使用；「不支持休眠」只在实际用到它时才成立。

官方列出的三个适用条件（无可用 slide、强制 slide=0、KASLR 不支持即 10.7 或更早）在当前配置下确实都不满足，但启用它只是提供一个兜底，不是常驻风险；关掉反而会在低位内存被占用时失去退路。因此保留 True，本次不改。

这条也说明了一件事：官方说明里「适用条件不满足」与「必须关闭」不是一回事，逐条判定不能只看前半句。

04

内存映射组：核对后无需改动

22 项 Booter Quirks 与官方默认、以及 config27（能启动的那份）逐项完全一致，6 项非默认值都是自洽的现代组合：

Quirk官方默认当前值判定
RebuildAppleMemoryMapFalseTrue官方 :1621「固件支持 MAT 时请改用 Rebuild」→ 正确
EnableWriteUnprotectorTrueFalse与上一项互斥，二选一已选对
SyncRuntimePermissionsFalseTrue官方 :1901，2017 后固件常见需求
ProtectUefiServicesFalseTrue官方 :1743，主要面向 VMware / GRUB 链式；此处属增益保护
ResizeAppleGpuBars-10官方 :1843「唯一支持的值就是 0」→ 正确
AllowRelocationBlockFalseTrue按需启用的兜底，见第 03 节

其余 16 项与官方默认一致；SetupVirtualMap=True 也是官方默认值。此外 SecureBootModel=Disabled 与 FixupAppleEfiImages=True 成对、UEFI.ResizeGpuBars=-1 与 Booter 侧缩小 BAR 分工明确，均无冲突。

官方在 Troubleshooting 里明确写过：RebuildAppleMemoryMap、EnableWriteUnprotector、ProtectMemoryRegions、SetupVirtualMap、SyncRuntimePermissions 这 5 项即使在相似硬件上也没有确定取值方法，可能要试遍所有组合。所以本次对照没有擅动这一组——它属于「启动结果反馈」才能定值的类别，不是查表能改的。
